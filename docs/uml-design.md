### 1.3 关系说明与建模理由

- **`查询合理乘车路线` …«include»…> `查询最短路线`**
  合理路线的里程上限为「最短路程 × 1.5」，必须先求出最短路程与最少换乘次数才能剪枝，因此每次执行合理路线查询都必然执行最短路线计算，属于强制性包含。
- **`查看分段乘车指引` …«extend»…> `查询合理乘车路线`**
  用户得到候选路线后，可以选择某条路线查看分段指引；也可以只看里程/换乘信息而跳过展示，属于可选扩展。
- **`计算票价` …«extend»…> `查询合理乘车路线`**
  用户在候选路线中选定一条后才进入计价，计价不是每次查询必经步骤。
- **`计算单程票价` / `计算武汉通票价` / `计算定期票票价` 泛化 `计算票价`**
  三者是同一计价用例的三种支付方式特化，费用规则不同（单程按段计价、武汉通 9 折、定期票单次 0 元），符合泛化关系。
- **`subway.txt` 不作为参与者**
  线路里程数据在系统启动时一次性读入内存（`MetroNetwork.load`），是全局前置条件，而不是在用例执行期间交互的外部角色。

## 二、用例详细描述：查询合理乘车路线（UC-06）

### 2.1 基本信息

| 项目 | 内容 |
| --- | --- |
| 用例编号 | UC-06 |
| 用例名称 | 查询合理乘车路线 |
| 参与者 | 乘客（主要参与者） |
| 涉及模块 | 线路查询模块（路网建模、最短路径、最少换乘、候选路径生成与筛选） |
| 用例目标 | 为乘客提供从起点站到终点站、**不重复经过站点**且**绕行与换乘均可接受**的候选路线集合，按总里程升序排列，最多 10 条 |
| 前置条件 | ① 系统启动时已成功加载 `subway.txt` 并构建路网（当前数据：12 条线路、274 段区间、250 个车站、33 个换乘站）；② 乘客已进入线路查询界面并选择「合理乘车路线」功能 |
| 触发条件 | 乘客提交起点站名称与终点站名称 |
| 后置条件 | 成功：界面展示候选路线列表（总里程、站数、换乘次数），选定一条后可查看分段乘车指引并进入计价；失败：给出明确的错误提示，路网数据不被修改 |
| 对应功能点 | 需求 3) 全部路径集合（无环约束）、4) 最短路径、5) 分段展示 |

### 2.2 主事件流

1. 系统提示乘客输入起点站与终点站。
2. 乘客输入起点站 `A`、终点站 `B`。
3. 系统校验 `A`、`B` 均为路网中的有效站名（见 4.1、4.2）。
4. 系统以 `A` 为源点运行 Dijkstra，得到最短站序 `P_min`，其里程记为 `D_min`。
5. 系统以 0-1 BFS 在「(站点, 线路)」状态图上计算从 `A` 到 `B` 的**全局最少换乘次数** `T_min`（同线移动代价 0，换线代价 1）。
6. 系统以深度优先搜索枚举从 `A` 到 `B` 的简单路径（用访问集合保证不重复站点），并做三重剪枝：
   - 累计里程超过 `1.5 × D_min` 的分支立即回退；
   - 增量维护「到达当前站时各可能线路的最少换乘数」，其最小值超过 `T_min + 2` 的分支立即回退；
   - 候选总数达到安全上限 `50000` 时停止枚举，保证响应时间。
7. 对每条候选路径，系统计算三项指标：总里程（保留 3 位小数）、经过站数、换乘次数（按该站序在各区间可选线路中取换乘最少的一种）。
8. 系统按（里程，站数，换乘次数）升序排序，做 **Pareto 去支配**：若某路线在里程、站数、换乘次数三项上均不优于另一条且至少一项更差，则删除；三项完全相同的不同路线同时保留。
9. 系统截取前 10 条作为「合理乘车路线」返回并展示。
10. 乘客选择其中一条路线，系统调用分段展示功能，输出「先乘 2 号线从 A 站到 B 站，在 B 站换乘 4 号线到 C 站」式的简洁指引，并给出换乘次数（扩展流：进入计价，见 3.2）。

**运行示例**（数据来自 `Test` 的实际输出，天河机场 → 武汉东站，`D_min = 47.794 km`，`T_min = 0`）：

| 序号 | 里程(km) | 站数 | 换乘 | 说明 |
| --- | --- | --- | --- | --- |
| 1 | 49.528 | 31 | 2 | 里程最短的候选 |
| 2 | 52.584 | 33 | 0 | 全程 2 号线直达，里程略长但零换乘 |

两条路线互不占优（第 1 条里程短但换乘多，第 2 条换乘少但里程长），因此都被保留。

### 2.3 扩展流

3.1 **起点与终点为同一站**：系统返回 1 条「原地不动」的路线（里程 0、站数 1、换乘 0），并提示无需乘车。
10.1 **乘客放弃选择**：用例正常结束，不进入分段展示与计价。
10.2 **乘客继续计价**：转入 UC-08 计算票价，单程票按区间计价，武汉通按 9 折，定期票记 0 元。
6.1 **候选数量达到安全上限**：停止继续枚举，对已收集的候选执行第 7～9 步，并在结果中注明「已达到候选上限，结果可能不完备」。

### 2.4 异常流

4.1 **起点站名不存在**：系统提示「未知站点：<输入值>」，用例结束，不展示任何路线。
4.2 **终点站名不存在**：处理方式同 4.1。
4.3 **起点与终点之间不连通**：系统提示两站之间不存在可达路径，用例结束（当前 12 条线路构成连通网络，此异常为通用防御）。
4.4 **输入为空或仅含空白字符**：按 4.1 处理，提示站名不能为空。

### 2.5 业务规则

| 编号 | 规则 |
| --- | --- |
| BR-1 | 两站之间的里程取所有区间数据中的**最小值**（共线区间只计一次，如 2/4 号线「中南路—洪山广场」0.966 km；6/16 号线「老关村—国博中心南」取 1.57 km 而非 1.826 km）。 |
| BR-2 | 一条路线的换乘次数 = 该站序下所有可行线路分配方案的换乘次数最小值，而非固定按线路名切分。 |
| BR-3 | 「合理乘车路线」须同时满足：① 无重复站点（无环）；② 里程 ≤ 最短里程 × 1.5；③ 换乘次数 ≤ 全局最少换乘次数 + 2；④ 删除被另一条路线在里程、站数、换乘次数上全面占优的路线；⑤ 按里程升序，最多返回 10 条。 |
| BR-4 | 「全局最少换乘次数」与里程无关，由 0-1 BFS 单独计算，不受最短路径的线路选择影响。 |

### 2.6 非功能要求

- 单次查询响应时间 ≤ 1 s（当前数据规模下实测毫秒级）；
- 路径枚举必须带剪枝与数量上限，避免组合爆炸导致界面卡死；
- 所有非法输入以异常对象而非错误码的形式抛出，交由界面层统一提示。

### 2.7 与代码的对应关系

| 步骤 | 实现位置 |
| --- | --- |
| 校验站名 | `MetroNetwork.requireStation` |
| 最短站序 | `MetroNetwork.shortestPath`（Dijkstra） |
| 查距离 | `MetroNetwork.pathDistance` |
| 全局最少换乘 | `MetroNetwork.minTransfers`（0-1 BFS） |
| 枚举 + 剪枝 | `MetroNetwork.collectRoutes`（上限 `MAX_ROUTE_CANDIDATES = 50000`） |
| 排序 + 去支配 + 截断 | `MetroNetwork.reasonableRoutes`（`MAX_REASONABLE_ROUTES = 10`） |
| 路径对象 | `MetroNetwork.Route`（里程/站数/换乘） |
| 分段展示 | `MetroNetwork.rideSegments` + `MetroNetwork.printRoute` |

### 3.2 类职责

| `MetroNetwork` | `subway.core` | 核心路网模型与全部查询算法：站点/线路索引、区间里程、最短路径、最少换乘、合理路线生成、分段展示 | `lines`、`stationLines`、`adjacency`、`segmentLines`、`reasonableRoutes`、`shortestPath`、`minTransfers` |

| `MetroNetwork.RideSegment` | `subway.core` | 分段值对象：某段乘坐的线路、上车站、下车站 | `line`、`from`、`to` |
| `MetroLine` | `subway.model` | 单条线路：站点序列与相邻区间里程，追加区间时校验首尾衔接 | `name`、`stations`、`segmentKm`、`appendSegment` |
| `StationDistance` | `subway.model` | 功能 2) 的结果值对象：站点、所在线路集合、距查询站点的距离 | `station`、`lines`、`km`、`toString` |
| `FareCalculator` | `subway.pricing` | 计价工具类，与路网完全解耦 | `singleFare`、`wuhanTongFare`、`periodPassFare` 及票价常量 |
| `InvalidInputException` | `subway.exception` | 受检异常：站名不存在、距离上限为负、起终点不连通等输入违规 | 继承 `Exception` |

### 3.3 关键设计说明

1. **站点以站名 `String` 唯一标识**，不再单独建 `Station` 类。
   武汉地铁站名全网唯一，用字符串既简化了 `Map` 索引，也避免了「同一站名对应多条线路」需要拆分类的冗余；站点所属线路统一由 `MetroNetwork.stationLines` 维护（即功能 1) 返回的「换乘站」数据结构）。
2. **`adjacency` 只存最小里程**。
   2/4 号线共用「中南路—洪山广场」，6/16 号线共用「老关村—国博中心南」但两线里程不同；建图时按站点对去重并取较小值，保证最短路计算无重复边。
3. **`segmentLines` 支撑共线段择线**。
   每个区间记录「有哪些线路经过」，用于计算某条站序的最小换乘次数、生成 `RideSegment` 分段，以及打印换乘指引。
4. **算法职责内聚在 `MetroNetwork`**：Dijkstra（最短路径与距离查询）、0-1 BFS（最少换乘）、带剪枝 DFS + Pareto 去支配（合理路线）均为私有方法，对外只暴露查询语义的公有方法。
5. **计价与路网分离**：`FareCalculator` 为纯静态工具类，只接收里程，便于单独测试与后续调整票价规则。
6. **类图仅展示主要方法**：`dijkstra`、`collectRoutes`、`minTransfers` 等私有辅助方法按题目要求省略细节，仅保留语义。

## 四、出图方式

`docs/*.puml` 为 UTF-8 编码的 PlantUML 源码，任选一种方式生成图片。

### 方式 A：在线渲染（最快，无需安装）

1. 打开 <https://www.plantuml.com/plantuml/uml/>；
2. 把 `use-case-diagram.puml` 或 `class-diagram.puml` 的内容粘贴到左侧编辑区；
3. 右侧即生成图形，可直接下载 PNG / SVG（用于插入实验报告）。

> 注意：在线方式会把源码发送到公共服务器，仅含课程设计内容时无影响。

### 方式 B：本地命令行（需 Java，本机已具备）

```bash
mkdir -p tools
curl -L -o tools/plantuml.jar https://github.com/plantuml/plantuml/releases/latest/download/plantuml.jar
java -jar tools/plantuml.jar -tpng docs/use-case-diagram.puml docs/class-diagram.puml
```

生成的 `docs/use-case-diagram.png`、`docs/class-diagram.png` 可直接插入报告。
若提示缺少 Graphviz，可在 `.puml` 首行 `@startuml` 之后添加 `!pragma layout smetana` 再渲染，或安装 Graphviz：<https://graphviz.org/download/>。

### 方式 C：VS Code 插件

安装扩展 `PlantUML`（jebbs.plantuml），打开 `.puml` 文件后按 `Alt + D` 预览，右键可导出 PNG/SVG。
